# REVIEW-S6-2026-11-09: WO-17 golden vectors (a34b809, 13f9692, 8b095d3)

Reviewer: sd-adc-design-reviewer. Read-only; one local parse of `golden/s6_vectors.json`. The coordinator saved this from the reviewer's returned text.

## Verdict
**Accepted with conditions.** The vectors are exact and deterministic. The exclusive-S convention (k/c1 = 4) is anchored to the loop physics: the residue identity has worst error 0, while inclusive S would be off by 0.0268 FS (PROVEN).

There are no Critical findings and 3 Major ones. Each Major lets a C9 RTL pass the golden set and still be wrong on silicon.

**S7 is blocked by about 9 SPEC rows (§5), not by the data.** The golden additions (M1–M3, m8–m10) are needed before C9.

## Major

**M1. Forced y[0] cannot be tested at RTL.**
- All 500 frames have ybits[0] = 1 (golden.py:59 asserts it). A testbench that drives the comparator input with ybits therefore cannot tell a forcing RTL from a pass-through RTL. The F8 bug (≈ 4/N FS, sporadic) would pass C9.
- Fix:
  - Add a README / C9 rule: the comparator bit at cycle 0 and throughout the reset window is junk (random, or the inverse of ybits[0]).
  - Add a "no forcing" RTL mutant.
  - Optionally add a per-frame `comp_raw0` field.

**M2. Sequencer control outputs are not in the golden set.**
- These are not checked: sys_swap timing relative to analog reset release, OTA-chop phase at cycle 0 and in reset (rule 7), acc_clear on the same edge as the reset release (rule 11), y_force timing, and the chop-sign tag coming from the same flop as the swap.
- `swaplate` is loop-level only and cannot be applied to an RTL testbench that feeds ybits. A tag/swap mismatch is invisible.
- Fix:
  - Add a cycle-level control trace: N = 64, two pairs, one config change. Per clock it holds rst_analog, acc_clear, sys_swap, ota_chop_phase, y_force, bit_valid and the raw pin.
  - Mutants: swap late, acc_clear ±1 clock, wrong OTA-chop phase restart, tag taken from a different flop.
  - This needs SPEC values for the reset window length (in fs clocks) and fch/fs with the phase at cycle 0.

**M3. Internal short / mode is neither a latched config nor a tag.**
- Rule 10 omits it, so a short toggled mid-pair gives a mixed pair that is still tagged valid. The frame also has no sys_en / ota_en / short bits.
- Fix: add short and mode to the rule-10 set, add 3 tag bits, and add a short-only toggle vector.

## Minor
- **m1. Order-1 acc2 is null.** Define it, preferably as "keeps accumulating ΣS". With null, y-flip misses 48 order-1 frames.
- **m2. First pair after rst_n is not flagged invalid.** It is the likeliest bad pair (CMFB, decap and bias start-up). Treat the rst_n release as a config change (cost: ≤ 1 pair), or justify the choice in SPEC.
- **m3. Latch rule is defined in slots.** It needs a clock-level definition: the shadow register is copied on edge E of the even-slot reset window; a write on or after E goes to the next pair; the last write wins. Add 2 sequencer vectors.
- **m4. Chop-sign order (+ even, − odd) is a convention.** Add it to SPEC. Drop +−−+ (rule 12) from v1, or make it a config bit.
- **m5. Wire format.** The chop_sign bit value, field widths, wrap rules, and frame_ctr reset on change (golden: no reset) are undefined, as is how the "valid" pin relates to the `invalid` tag. Add a frame-layout table.
- **m6. PGA.** It appears in the SPEC §3.8 config, while golden has pga = null. Delete it or define it.
- **m7. OTA-only chop (ota 1, sys 0) is reachable but missing.** D4 says it is never used alone. Either the RTL forces sys when ota is set (show this in a vector), or the combination is allowed for characterisation (add a vector and fix V4).
- **m8. Accumulator edges are never reached.** Max |acc2| is 7,533,166 (0.898·2^23) and max |acc1| is 3,686, so a 13-bit acc1 passes. Add synthetic RTL-only streams (all +1, +1 then all −1, alternating) at N 4096, plus an acc1-width mutant.
- **m9. frame_ctr wrap is never exercised** (max 11). Add a sequence of at least 258 frames at N 64 that reuses one frame's ybits.
- **m10. Sys-chop pairs are exactly symmetric** (160/160). Add dyadic-offset vectors (u_eff = s·u + off): a correct pair returns u, a misaligned one returns ±off.
- **m11. README must say which fields are RTL-observable** (acc1, acc2, tags, ybits/raw pin) and which are references (num*, pair*, model_ref). SPEC: "accumulators in the modulator frame, no sign applied".

## Efficiency
- Dropping pair_idx saves about 8 tag bits per frame, net about 5 after the M3 tag bits.
- Keep the single internal-short point; the real check is C8/V4.
- File size is fine; the wrap sequence reuses stored ybits.
- An RTL-shaped N±1 mutant (stream truncated/extended with den fixed) is cheaper than re-running the loop.

## Verification gaps (before C9)

- M3 short/mode toggle and tags.
- Sequencer mutants: mid-pair latch, invalid on the first frame only, frame_ctr reset on change, invalid at rst_n.
- Accumulator mutants: no clear, stream truncate/extend, 13-bit acc1.
- m8 edge streams.

- m7 OTA-only vector or rule.

- Assert `u_hat_signed·den == num_signed` (500/500 hold, but it is not tested).
- V4 tolerance per mode from the S3 budget: compare residue-corrected u, not bits.
- Accepted as is: single short point, fs_div (checked in the M2 trace / STA), PGA null once the SPEC row is resolved, and the OTA-chop mutant at control level only.

## What held up
- Dyadic exactness, with the integer loop regenerating all bitstreams.
- Determinism, with the sha pinned.
- The physics anchor for exclusive S, and the order-1 branch pinned (closes REVIEW-S5h §3).
- The width mutant: 18 frames reject at N 4096 with 23 bits; 24 bits pass.
- The F8 `y0free` mutant targets the right bug class; the `y0alt` insight holds.
- The drop and config-change sequences behave correctly.
- The iadc.py change is minimal.
- Raw-accumulator output keeps k/c1 in firmware, which is a good choice.

## §5. S7 blockers (SPEC text only)
1. The y[0] forced value and its scope.
2. Chop-sign order, and whether +−−+ stays.
3. Frame-layout table (bits, widths, wrap, frame_ctr reset, valid pin vs invalid tag).
4. Clock-level config latch, last write wins.
5. Invalid scope (short/mode; rst_n).
6. Order-1 acc2 value.
7. OTA-only chop: forbidden/forced, or allowed.
8. PGA row: delete or define.
9. Reset window length in fs clocks; fch/fs and the OTA-chop phase at cycle 0.

Questions:
- How is order 1 built in the analog: comparator on x1, or int2 bypassed or used as a sample-and-hold? An extra delay changes the bitstream.
- Is the raw bitstream pin defined during reset? Is there a frame strobe?
- Must a frame be read out within one slot, or is it double-buffered (which defines "dropped")?
