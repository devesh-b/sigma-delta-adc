### Parallel runs: `scripts/lpool.sh JOBFILE LOGDIR`
- It sizes parallelism to the server load, AND all pools share a global cap of GMAX=5 slots (flock, 2026-11-14). Never export OMP_NUM_THREADS before calling it; it sets it per job itself. Heavy formal runs: alone, with ulimit -v (a 10.6 GB PDR froze the box 2026-11-14).
- It writes `POOL_DONE` when finished and an `EXIT=` line in each job log.
- Use a single-thread `.spiceinit` in the frozen copy.
- Use absolute output paths: ngspice runs with another working directory, and relative paths broke WO-52 and WO-61.
- The launcher must source the venv and the nix PATH. Without them ngspice is not found and jobs fail instantly.
- Two bugs fixed on 2026-11-13: nproc read OMP_NUM_THREADS, and the running-job count was wrong. Pools are now tested and throttle correctly.

### Waiting on runs
- Never use pgrep/pkill wait loops over ssh; they match themselves.
- Never use `pkill -f` over ssh at all.
- Wait on the POOL_DONE/EXIT markers with spaced single checks, or with one background watcher.

### Git
- Atomic commits with explicit paths (`git commit -- <paths>`). No stash. **No attribution trailers. Never push** without an OK.
- Signing goes through the 1Password agent. When it is locked, commits fail with "failed to fill whole buffer / agent returned an error" and ssh can fail too. Never bypass it; ask the user to unlock, and keep a list of uncommitted paths. It locks often.

### Agents

- Tiering: Opus plans, reviews and does design work. Sonnet writes code. `sd-adc-design-reviewer` reviews every design change. `rtl-verification-engineer` writes the C9 bench and never edits RTL. `pd-expert` does PnR.

### Verification and reporting
- **Green is not proof.** Every check needs a broken copy that REJECTs. A blind check is a finding, not a pass.
- SPEC is frozen. Change it only through change-log entries (CL-n) that cite a decision ID. **Loosening a gate is the user's decision.** Ask with options and a recommendation.
- Nothing outward-facing: no TT repo, no GitHub, no push.

## 2. Decision-quality lessons (apply every time)

1. **Never decide on a single unverified bench.**
   - D62 was decided on a latched tb9 bench (Cint positive feedback), and D63 had to correct it.
   - Before trusting a "pass", check that the bench can fail.
2. **Watch for simulator artefacts.** All of these have looked like design results:
   - silent "Transient op" fallback (now a lint error);
   - non-physical .dc solutions, e.g. V_A ≈ −1400 V (WO-50/55);
   - "empty netlist", which actually means "timestep too small" in batch mode (WO-54/70);
   - empty output files from relative paths (WO-52 tb7 produced NO data).

   Check that a result file actually contains data before reporting numbers.
3. **Test the stimulus as well as the circuit.**
   - The C3 T8 stress failure first looked like a stimulus artefact. At realistic slew it was a real latch issue: a floating stack node, fixed in rev e.
4. **Rules can be stricter than physics.** The fix is to ask the user to define the rule, not to loosen it ourselves:
   - D80: junctions vs oxide;
   - D83: sustained vs < 1 ns overshoot;
   - D86: slew waiver at the stand-in corner.
5. **One change per PnR run, every check re-run.**
   - WO-67's cell ban made things worse, and was reverted in 8ddea05.
   - A revert can fail on a dirty tree. Restore the single file and commit it, then verify that the next agent's frozen copy uses it.
6. **Proxies and margins.** Several rows were proxies: f_cm, the 0.2·t_half tb9 timing, the 1.4 pF SR basis, the 20 mV comparator offset, the 250 µV noise. Rows were re-based on physical impact only with a user decision (D63, D65, D71, D75).
7. **Re-check the cross-block budgets when a block changes:**
   - **Fast-mode current:** ≈ 180 µA nominal (REASONED) against the 172 µA estimate and the 200 µA budget.
   - **x2 peak:** 1.41 V, at the edge of OTA2's 1.4 V range.
   - **Comparator CM kick:** ≈ 40–48 mV into OTA2's CMFB.
   - **vg leakage:** 150 pA, handled by D82.
8. **Ask, don't assume,** when the user owns the choice. The user asked to be asked about every C9 ambiguity individually (D66).
